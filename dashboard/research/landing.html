How StegnoZ works: four connected stages

The pipeline reads varied hospital exports, detects personal data, links patient records and verifies each candidate release against the configured privacy policy.

Stage 01translate

Ingest mixed hospital files

Read CSV, TSV, JSON, FHIR R4 and notes. Detect identifiers in English, Hindi and Hinglish. Quarantine malformed or unsupported files.

Supported inputs: CSV · TSV · JSON · FHIR R4 · notes
Stage 02rule

Preserve clinical meaning

Remove personal details while retaining diagnoses, medicines, dosages, vitals and laboratory values where the parser can identify them.

Verification: residual identifier checks and file status
Stage 03fingerprint

Link patient histories

Compare identifier and name evidence across files with conflict checks and Fellegi–Sunter scores. Assign keyed pseudonymous IDs.

Output: consistent IDs across linked records
Stage 04security

Select and verify policy

Search age, location and PIN generalization choices against observed risk. Apply patient-consistent date shifts and withhold a release when strict risk rules fail.

Output: sanitized files · report.json · records.jsonl
